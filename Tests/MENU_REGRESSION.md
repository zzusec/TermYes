- 菜单操作必须产生目标行为，失败须可见，不以构建成功或配置文件存在作为功能验收。
- Agent 的勾选要求当前配置有效、真实模型请求成功、安全 Shell 无人工确认执行成功，以及客户端实际调用命令守卫的证据。异常退出、超时、文件/CLI 变化及超过 24 小时的记录不能继续作为通过依据。

## Ctrl-C reviewer

原模型和 endpoint 保持不变。原输出预算 1200 时实际返回 thinking 而无最终 text，按安全契约拒绝；提高本机已有 `max_response_tokens` 到 4096 后，真实 reviewer 返回有效最终判定并通过实测。未把 thinking 当作判定，也未添加不受该模型支持的关闭 thinking 参数。原配置备份保留在本地证据目录（权限 `0600`）。

辅助功能旧签名记录重新授权后，菜单确认显示“正在监听 Ctrl-C 确认窗口”。专用 Terminal 假确认框的完整链路实测通过：真实 reviewer 返回 allow，确认键只发送到该测试窗口，窗口生成 `confirmed-by-targeted-return` 落地标记；对应 `window-approval-history.jsonl` 记录 allowed=true。第一次 90 秒 fixture 因 reviewer 超时/迟到回复而失败，应用正确取消过期窗口确认；延长测试窗口存活到 240 秒后通过，没有放宽权限、置信度或窗口复核。不能以系统开关为 on 或 reviewer API 通过代替投递成功。
